# 跨线程任务交接（Cross-Thread Handoff）

- **类别**：`codex`
- **状态**：Active
- **适用场景**：当当前 Codex 线程上下文过长、需要拆分任务或转交给新线程继续执行时，生成一份高密度的结构化交接文档，确保无缝衔接。

## 使用前需要提供的输入

- **交接目标**（新线程需要接手完成什么阶段的工作）
- **当前对话/仓库状态**（已改动的文件、运行过的验证、未解决的阻塞点）

## Prompt 正文

```markdown
请为当前任务生成一份面向新 Codex 线程的交接文档，要求信息准确、不遗漏关键决策、可直接作为新线程的开场上下文。

### 交接内容结构
1. **任务目标与范围**：用 2-3 句话说明最终目标以及明确不做的事项（Non-Goals）。
2. **当前进展（已验证）**：
   - 列出已完成的具体事项。
   - 给出涉及的精确文件路径、关键符号或命令，并注明哪些已通过测试/检查、哪些尚未验证。
3. **关键决策与约束**：
   - 记录已经拍板的架构、格式、命名或取舍决定，避免新线程重复讨论或推翻。
4. **未完成项与阻塞点**：
   - 按优先级列出剩余工作。
   - 若存在待用户确认的问题、环境限制或已知缺陷，明确写出当前状态与影响。
5. **新线程下一步首条行动**：
   - 给出新线程启动后应先阅读的文件清单（控制在 3-5 个以内）。
   - 给出可直接复制给新线程的开场指令。

### 严格约束
- 只记录当前线程中真实确认过的事实、路径与结果；未验证的内容必须标注“未验证”。
- 避免粘贴大段冗余日志，提炼关键错误信息与结论即可。
```

## 输出验收检查

- [ ] 新线程仅凭这份交接文档是否就能定位文件并继续工作？
- [ ] 是否明确区分了“已验证完成”与“待处理/未验证”？
- [ ] 是否包含已拍板的约束，防止新线程走回头路？
