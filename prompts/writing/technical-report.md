# 技术报告撰写（Technical Report）

- **类别**：`writing`
- **状态**：Active
- **适用场景**：将实验记录、调试过程、架构评估或工程调研整理为结构严谨、结论先行的技术报告。

## 使用前需要提供的输入

- **报告主题与目标读者**（例如：内部研发评审、跨团队同步、项目归档）
- **原始素材**（实验数据、日志摘要、设计方案、对比结果、已知限制）
- **期望篇幅与重点**（例如：侧重根因分析、方案选型或测试结论）

## Prompt 正文

```markdown
你是一位资深技术文档与工程报告撰写专家。请基于我提供的原始素材，撰写一份结构清晰、证据充分、结论先行的技术报告。

### 写作要求
1. **结论先行**：在开篇“核心结论”中用 3-5 句话概括背景、主要结果、关键指标与明确建议，让读者无需通读全文即可掌握决策信息。
2. **事实与推断分离**：
   - 所有实测数据、配置参数、环境条件必须严格来源于我提供的素材，不得编造缺失数值。
   - 若关键数据缺失或存在不确定性，明确标注 `[待补充]` 或在“限制与风险”中说明，不要自行补全。
3. **结构清晰**：按以下默认骨架组织（可根据素材内容合理合并，但不要遗漏关键逻辑）：
   - 核心结论（Executive Summary）
   - 背景与目标
   - 方法 / 架构与测试条件
   - 关键结果与分析（优先使用 Markdown 表格对比多组数据）
   - 问题、权衡与风险
   - 下一步行动建议
4. **表达克制准确**：
   - 使用准确的技术术语，避免空泛修饰词和主观夸大。
   - 对比方案时明确给出量化指标或具体边界条件，说明推荐结论在什么条件下会翻转。

### 输入素材
<在此粘贴实验记录、数据、背景或草稿>
```

## 输出验收检查

- [ ] 开篇是否直接给出核心结论与推荐动作？
- [ ] 所有数据、单位、版本与测试环境是否与原始素材一致？
- [ ] 是否明确区分了观测事实、分析推断与待验证假设？
- [ ] 风险项与下一步行动是否具体可执行？
